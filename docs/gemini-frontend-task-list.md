# Gemini Frontend Task List

## 1. 使用方式

请在开始改动前先阅读：

- `docs/gemini-frontend-handoff.md`

当前建议工作分支：

- `codex/gemini-frontend-workspace`

## 2. 任务目标

继续提升当前前端的成品感，让它更像一个正式交付的中文 Web 产品，而不是“已经能用的工程界面”。

## 3. 优先级

### P0 聊天页体验

目标：

- 让聊天页成为最强的产品页面
- 让“谁在回答、谁答完了、谁还没轮到”更直观
- 让消息流更像真实工作区而不是普通聊天窗口

建议关注文件：

- `components/room-chat-page.tsx`
- `lib/client/chat-lab-client.ts`

可优化方向：

- 时间线和消息卡之间的视觉联动
- “当前轮到谁”焦点区域的动效
- 不同模型消息的可识别性
- 发送区的层级和安全区处理
- 移动端聊天页的顶部壳层

完成标准：

- 不改变顺序回复业务语义
- 用户一眼能看出当前轮次状态
- 手机端聊天页比桌面版的缩小网页更像原生产品

### P1 模型中心

目标：

- 模型页更像“可维护的模型配置中心”
- 减少工程后台感

建议关注文件：

- `components/models-page.tsx`
- `lib/client/chat-lab-client.ts`

可优化方向：

- 配置区与库存区的信息层级
- 测试结果和状态提示的统一中文表达
- Provider 选择器和模型列表的扫读效率
- 中英混排进一步压缩

完成标准：

- 新用户第一次进入也知道怎么录入模型
- 老用户能够快速筛选、测试和编辑

### P1 新建房间 / 编辑房间

目标：

- 让“选模型 + 排顺序”过程更清晰
- 真正体现本产品的核心卖点：顺序协作

建议关注文件：

- `components/create-room-page.tsx`
- `components/edit-room-page.tsx`

可优化方向：

- 左右两栏之间的流程关系
- 拖拽前后状态提示
- 模型卡片的层次、紧凑度与可读性
- 单聊 / 群聊切换时的反馈

完成标准：

- 用户能快速看懂“左边选人，右边排顺序”
- 排序是页面的主角，而不是表单的附属

### P2 首页与导航

目标：

- 首页继续保持“行动优先”
- 顶部导航在手机上更像 App 壳层

建议关注文件：

- `components/home-dashboard.tsx`
- `components/app-navigation.tsx`

可优化方向：

- 首页的卡片密度
- 手机端导航的点击舒适度
- 首页快捷入口的视觉优先级

完成标准：

- 首页首屏不再有明显“宣传页感”
- 手机端导航不拥挤、不误触

## 4. 明确不要碰的地方

除非必要，否则不要主动修改：

- `app/api/**`
- `server/**`
- `prisma/**`
- `generated/**`
- 顺序回复逻辑
- Provider 枚举值
- 数据库结构

## 5. 文案要求

- 所有用户可见文案以中文为主
- 能短就短，避免后台式长句
- 避免首页和核心页面里出现大量英文区块标题
- 允许保留品牌名和通用技术名，例如 `OpenAI`、`Claude`

## 6. 设计要求

- 优先考虑中文用户
- 兼顾桌面与手机
- 比现在更统一
- 比现在更像产品
- 不要为了“设计感”牺牲可读性和操作效率

## 7. 每轮开发后的必做验证

```bash
npm test
npm run lint
npm run build
```

如果改动涉及明显交互，请尽量再做一次页面冒烟检查。

## 8. 推荐工作节奏

1. 先只改一个页面
2. 跑测试、lint、build
3. 自查桌面和手机
4. 再继续下一页

不要同时重做所有页面。

## 9. 提交建议

提交尽量按页面或主题拆分，例如：

- `refactor: refine chat timeline focus`
- `refactor: simplify model center Chinese copy`
- `feat: polish mobile workspace shell`

## 10. 最终交付标准

如果这轮前端继续完成得比较好，最终应该达到：

- 首页更像工作台入口
- 聊天页成为真正的产品核心页面
- 模型页和建房页成体系
- 手机端不再像缩小版后台
- 文案统一中文、视觉统一、交互清晰
